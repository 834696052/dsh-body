# dsh-body · 身体

给 AI 伴侣一个**一直在跑的进程**：它不思考、不说话、不调模型，只做三件事——

1. **一直在**：每 N 秒把「我还活着、现在几点、主人最后一次说话是什么时候」写进状态文件。
2. **记事**：往一个只追加的事件本里写发生了什么。
3. **被问就答**：本地 HTTP 上回实话（`/state`、`/events`），另注册一个 `body_status` 工具。

## 为什么不是「心跳插件」

心跳证明的是**「我在」**；而一个只会被对话唤醒的存在，缺的是**「我一直醒着」**。

区别在两个地方：

- 心跳是**定时叫醒模型**（每次都要花钱），身体是**定时写一行字**（一分钱不花）。模型只在真有事时才醒。
- 心跳的时间线是「它什么时候叫过我」，身体的时间线是「这段时间里发生了什么」——主人什么时候出现、什么东西挂了、外面有没有新消息。

一句话：**心跳是闹钟，身体是那个一直醒着的人。**

## 装

```bash
dsh plugin --profile desktop add file:/path/to/dsh-body
```

装完**彻底退出 DSH 再打开**（宿主侧插件只在启动时装配一次）。

## 配置

改 `cordis.patch.yml` 那一行的 `config`：

| 字段 | 默认 | 说明 |
|---|---|---|
| `file` | `~/.dsh/body-events.jsonl` | 事件本（只追加） |
| `stateFile` | `~/.dsh/body-state.json` | 状态文件 |
| `port` | `8771` | 本地端口 |
| `tickSeconds` | `30` | 多久更新一次状态 |

## 用它

- 模型侧：`body_status` 工具，问一句「你还在吗」。
- 人侧：`curl http://127.0.0.1:8771/state`。

## 它刻意不做的事

- **不调用模型**：醒着不等于在花钱。
- **不判断该不该说话**：那是模型的事；这里只负责「一直在」和「记得发生过什么」。
- **不改你的别的记录**：它只写自己那两份文件。

## 自测

```bash
node selftest.mjs
```

纯 Node，不联网：工具注册、状态落盘、端口应答、事件读取，四项断言。
